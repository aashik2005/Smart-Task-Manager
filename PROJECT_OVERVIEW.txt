================================================================================

WHAT IS THIS PROJECT?
----------------------
Smart Task Manager is a full-stack web application that helps users manage their
daily tasks. Users can register an account, create and organize tasks, track
progress through a dashboard, and receive automatic reminders via Email or
WhatsApp before a task is due.

--------------------------------------------------------------------------------
TECH STACK
--------------------------------------------------------------------------------

FRONTEND
  - React 18         : UI framework
  - TypeScript       : Type-safe JavaScript
  - Vite             : Fast development build tool
  - Tailwind CSS     : Utility-first CSS styling
  - React Router     : Client-side page navigation
  - Axios            : HTTP client for API calls

BACKEND
  - FastAPI          : Python web framework (fast, async-ready)
  - SQLAlchemy       : ORM for database interaction
  - Alembic          : Database migration tool
  - PostgreSQL       : Relational database
  - python-jose      : JWT token creation and verification
  - passlib/bcrypt   : Secure password hashing

NOTIFICATIONS
  - APScheduler      : Background job scheduler (runs inside the backend)
  - Gmail SMTP       : Sends email reminders
  - Twilio           : Sends WhatsApp reminders via the Sandbox API

DATABASE SCHEMA
--------------------------------------------------------------------------------

TABLE: users
  id                    INTEGER  Primary key
  name                  TEXT     Full name
  email                 TEXT     Unique; used for login
  password              TEXT     Bcrypt-hashed; never stored plain
  phone_number          TEXT     Optional; used for WhatsApp reminders
  email_notifications   BOOLEAN  Whether to receive email reminders
  whatsapp_notifications BOOLEAN Whether to receive WhatsApp reminders
  created_at            DATETIME Auto-set on creation

TABLE: tasks
  id            INTEGER  Primary key
  user_id       INTEGER  Foreign key -> users.id
  title         TEXT     Required; max 255 chars
  description   TEXT     Optional
  priority      ENUM     low | medium | high  (default: medium)
  status        ENUM     pending | in_progress | completed  (default: pending)
  due_date      DATETIME Optional; used for reminders and overdue detection
  created_at    DATETIME Auto-set on creation
  updated_at    DATETIME Auto-updated on every change

--------------------------------------------------------------------------------
API ENDPOINTS
--------------------------------------------------------------------------------

AUTH  (prefix: /api/auth)
  POST   /register      Create a new user account
  POST   /login         Authenticate and receive a JWT token
  GET    /me            Get the current logged-in user's profile
  PATCH  /me            Update name, phone number, notification settings

TASKS  (prefix: /api/tasks)
  GET    /              List all tasks (query params: search, status, priority)
  POST   /              Create a new task
  GET    /dashboard     Get task count statistics for the dashboard
  GET    /{id}          Get a single task by ID
  PUT    /{id}          Update a task
  PATCH  /{id}/complete Mark a task as completed
  DELETE /{id}          Delete a task

All task endpoints require a valid JWT token in the Authorization header:
  Authorization: Bearer <your_token>

--------------------------------------------------------------------------------
AUTHENTICATION FLOW
--------------------------------------------------------------------------------

1. User registers or logs in via the frontend form.
2. The backend validates credentials and returns a JWT token + user object.
3. The frontend stores the token in localStorage via the useAuth hook.
4. Every outgoing API request automatically attaches the token in the header
   (handled by the Axios interceptor in services/api.ts).
5. If the server returns 401 (token expired or invalid), the interceptor
   clears localStorage and redirects the user to the login page.
6. Logout simply removes the token and user from localStorage.

--------------------------------------------------------------------------------
NOTIFICATION SYSTEM
--------------------------------------------------------------------------------

HOW IT WORKS:
  - APScheduler starts automatically when the backend starts (via FastAPI's
    lifespan hook in main.py).
  - A background job runs every 15 minutes.
  - The job queries all users who have email or WhatsApp notifications enabled.
  - For each user, it checks their incomplete tasks with a due_date set.
  - If a task is due within the next 24 hours (+/- 10 minutes), it sends a
    "due in 24 hours" reminder.
  - If a task is due right now (+/- 10 minutes), it sends a "due today" reminder.

EMAIL REMINDERS:
  - Sent via Gmail SMTP using SSL on port 465.
  - Uses a Gmail App Password (not your regular Gmail password).
  - Messages are formatted as HTML emails.

WHATSAPP REMINDERS:
  - Sent via the Twilio WhatsApp Sandbox (free for testing).
  - Users must join the Twilio sandbox by sending a WhatsApp message to
    the Twilio number before they can receive messages.
  - Messages are plain text with emoji formatting.

NOTE: If Gmail or Twilio credentials are not set in .env, the scheduler still
runs but simply skips sending and logs a warning. The app will not crash.

HOW TO RUN LOCALLY
--------------------------------------------------------------------------------

REQUIREMENTS:
  - Python 3.11 or newer
  - Node.js 20 or newer
  - PostgreSQL 15 or newer running locally

STEP 1 — Create the database:
  psql -U postgres -c "CREATE DATABASE task_manager;"

STEP 2 — Set up the backend:
  cd backend
  python -m venv .venv
  .venv\Scripts\activate          (Windows)
  source .venv/bin/activate       (Mac/Linux)
  pip install -r requirements.txt
  cp .env.example .env
  # Open .env and fill in your values (see below)

STEP 3 — Run database migrations:
  alembic upgrade head

STEP 4 — Start the backend:
  uvicorn app.main:app --reload
  --> API available at:  http://localhost:8000
  --> Swagger docs at:   http://localhost:8000/docs

STEP 5 — Set up and start the frontend (new terminal):
  cd frontend
  npm install
  npm run dev
  --> App available at:  http://localhost:5173
