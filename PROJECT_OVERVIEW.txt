WHAT IS THIS PROJECT?
----------------------
Smart Task Manager is a full-stack web application that helps users plan,
track, and complete their tasks with intelligent scheduling. It supports four
distinct task types, a streak and badge system for motivation, a calendar view,
rotating topic queues for recurring study/practice tasks, dark mode, and
automatic reminders via Email or WhatsApp.

--------------------------------------------------------------------------------
TECH STACK
--------------------------------------------------------------------------------

FRONTEND
  - React 18         : UI framework
  - TypeScript       : Type-safe JavaScript
  - Vite             : Fast development build tool
  - Tailwind CSS     : Utility-first CSS styling (with dark mode support)
  - React Router     : Client-side page navigation
  - Axios            : HTTP client for API calls

BACKEND
  - FastAPI          : Python web framework (fast, async-ready)
  - SQLAlchemy       : ORM for database interaction
  - Alembic          : Database migration tool
  - PostgreSQL 16    : Relational database
  - python-jose      : JWT token creation and verification
  - passlib/bcrypt   : Secure password hashing (bcrypt pinned to 4.0.1)

NOTIFICATIONS
  - APScheduler      : Background job scheduler (runs inside the backend)
  - Gmail SMTP       : Sends email reminders
  - Twilio           : Sends WhatsApp reminders via the Sandbox API

INFRASTRUCTURE
  - Docker + Docker Compose : Runs all three services (db, backend, frontend)
  - Nginx            : Serves the Vite production build inside Docker

DATABASE SCHEMA
--------------------------------------------------------------------------------

TABLE: users
  id                     INTEGER   Primary key
  name                   TEXT      Full name
  email                  TEXT      Unique; used for login
  password               TEXT      Bcrypt-hashed
  phone_number           TEXT      Optional; used for WhatsApp reminders
  email_notifications    BOOLEAN   Toggle email reminders
  whatsapp_notifications BOOLEAN   Toggle WhatsApp reminders
  current_streak         INTEGER   Consecutive active days (default 0)
  longest_streak         INTEGER   Best streak ever achieved
  last_activity_date     DATE      Date of last task completion
  total_completed        INTEGER   Lifetime completed task count
  badges                 JSON      List of earned badge keys
  created_at             DATETIME  Auto-set on creation

TABLE: tasks
  id                     INTEGER   Primary key
  user_id                INTEGER   Foreign key -> users.id
  title                  TEXT      Required; max 255 chars
  description            TEXT      Optional
  priority               ENUM      low | medium | high
  status                 ENUM      pending | in_progress | completed
  task_type              ENUM      one_time | daily | weekly | target
  category               ENUM      study | work | personal | health | others
  color_label            TEXT      Optional hex color (e.g. #FF5733)
  due_date               DATETIME  For one_time tasks; drives reminder offset
  start_date             DATETIME  For target tasks
  target_date            DATETIME  Deadline for target tasks
  recurrence_days        JSON      List of weekday names (e.g. ["monday","thursday"])
  reminder_time          TEXT      HH:MM for daily/weekly notification time
  reminder_offset_minutes INTEGER  Minutes before due_date to send notification
  progress               INTEGER   0-100; for target tasks
  notes                  TEXT      Optional free text / links
  is_active              BOOLEAN   Pause/resume recurring tasks
  sort_order             INTEGER   User-defined drag-and-drop order
  topic_queue            JSON      Ordered list of rotating topics (e.g. LLD problems)
  current_topic_index    INTEGER   Index into topic_queue for today's topic
  created_at             DATETIME  Auto-set on creation
  updated_at             DATETIME  Auto-updated on every change

TABLE: milestones
  id          INTEGER   Primary key
  task_id     INTEGER   Foreign key -> tasks.id
  title       TEXT      Milestone description
  completed   BOOLEAN   Whether this milestone is done
  due_date    DATETIME  Optional milestone deadline
  sort_order  INTEGER   Display order

TABLE: task_completions
  id               INTEGER   Primary key
  task_id          INTEGER   Foreign key -> tasks.id
  user_id          INTEGER   Foreign key -> users.id
  completed_date   DATE      The date this recurring task was completed
  UNIQUE (task_id, completed_date)   Prevents double-completing on same day

--------------------------------------------------------------------------------
TASK TYPES
--------------------------------------------------------------------------------

ONE-TIME
  A task that happens once. Has a due date and an optional reminder offset
  (e.g. 30 minutes before, 1 day before). Marking complete sets status to
  "completed" permanently.

DAILY
  A recurring task that resets every day. Shows in Today's Tasks every day.
  Has a reminder_time (HH:MM) for when to send the daily notification. Each
  completion is recorded in task_completions but the task itself stays active.
  Supports a Topic Queue (see below).

WEEKLY
  A recurring task that repeats on selected weekdays. Choose one or more days
  (e.g. Monday + Thursday). Shows in Today's Tasks only on matching weekdays.
  Has a reminder_time for when to notify on those days. Supports a Topic Queue.

TARGET (Goal-Based)
  A long-running goal with a start date, target date, and progress percentage
  (0-100). Supports milestones — sub-steps that can be checked off individually.
  Marking the task complete sets progress to 100% and awards the "goal_achiever"
  badge.

--------------------------------------------------------------------------------
TOPIC QUEUE  (rotating topics for daily/weekly tasks)
--------------------------------------------------------------------------------

PURPOSE:
  Some recurring tasks have the same habit but different content each day —
  for example, practising a different LLD (Low-Level Design) problem every day,
  or reading a different book chapter each week. The Topic Queue feature handles
  this automatically without needing a separate task per topic.

HOW IT WORKS:
  - When creating or editing a Daily or Weekly task, open the "Topic Queue"
    section in the task form.
  - Add topics in the order you want to do them (e.g. ATM Machine → Parking Lot
    → Library Management → Elevator System → Chess Game).
  - The highlighted topic (▶) is today's active topic.
  - The TaskCard shows a "📌 Today: ATM Machine" banner so you always know
    what to work on without opening the task.
  - When you mark the task complete, the index advances automatically to the
    next topic. After the last topic it wraps back to the first.
  - Topics can be reordered (↑ ↓) or deleted from the form at any time.
  - Tasks without a topic queue work exactly as before — this feature is
    fully optional.

EXAMPLE USE CASES:
  - Daily LLD practice: ATM Machine, Parking Lot, Library Management, ...
  - Weekly book reading: Chapter 1, Chapter 2, Chapter 3, ...
  - Daily coding problem: Two Sum, Merge Intervals, Binary Search, ...
  - Weekly language flashcard sets: Verbs, Adjectives, Phrases, ...

--------------------------------------------------------------------------------
STREAK & BADGE SYSTEM
--------------------------------------------------------------------------------

STREAKS:
  - Every day at least one task is completed, the current_streak increments.
  - Miss a day and the streak resets to 1 on the next completion.
  - longest_streak tracks the personal best.
  - Shown in the Navbar (🔥 5) and on the Dashboard streak card.

BADGES (automatically awarded):
  first_task           : Complete your very first task
  streak_7             : Achieve a 7-day streak
  tasks_30             : Complete 30 tasks total
  tasks_100            : Complete 100 tasks total
  consistency_champion : Achieve a 30-day streak
  goal_achiever        : Complete a Target task

--------------------------------------------------------------------------------
NOTIFICATION SYSTEM
--------------------------------------------------------------------------------

The scheduler (APScheduler) runs every 5 minutes inside the backend process.

FOR ONE-TIME / TARGET TASKS:
  - Notification fires at: due_date - reminder_offset_minutes (±2.5 min window)
  - If no offset is set, a fallback fires 24 hours before the due date.

FOR DAILY TASKS:
  - Notification fires at the reminder_time set on the task (HH:MM).
  - Skipped if the task was already completed today.

FOR WEEKLY TASKS:
  - Notification fires only on the task's recurrence days.
  - Same reminder_time logic as daily.

CHANNELS:
  - Email via Gmail SMTP (SSL, port 465) using a Gmail App Password.
  - WhatsApp via Twilio Sandbox (free for testing).

NOTE: If credentials are not set in .env, the scheduler runs but skips
sending and logs a warning. The app does not crash.

API ENDPOINTS
--------------------------------------------------------------------------------

AUTH  (prefix: /api/auth)
  POST   /register           Create a new user account
  POST   /login              Authenticate and receive a JWT token
  GET    /me                 Get current user profile (includes streak + badges)
  PATCH  /me                 Update name, phone, notification toggles

TASKS  (prefix: /api/tasks)
  GET    /                   List all tasks
                             Query params: search, status, priority,
                             category, task_type
  POST   /                   Create a task (includes topic_queue support)
  GET    /dashboard          Full dashboard data: stats, streaks, today/goal/
                             overdue task lists, badges
  GET    /calendar           Monthly task map: ?year=&month=
                             Returns { "2026-08-03": [task, ...], ... }
  POST   /reorder            Bulk update sort_order (drag-and-drop)
  GET    /{id}               Get a single task
  PUT    /{id}               Update a task (including topic_queue)
  PATCH  /{id}/complete      Mark task done; advances topic index for
                             daily/weekly tasks; updates streak and badges
  DELETE /{id}               Delete a task

MILESTONES  (prefix: /api/tasks/{task_id}/milestones)
  GET    /                   List milestones for a task
  POST   /                   Add a milestone
  PUT    /{milestone_id}     Update a milestone (title, completed, due_date)
  DELETE /{milestone_id}     Delete a milestone

All endpoints except /register and /login require:
  Authorization: Bearer <jwt_token>

--------------------------------------------------------------------------------
AUTHENTICATION FLOW
--------------------------------------------------------------------------------

1. User registers or logs in via the frontend form.
2. Backend validates credentials and returns a JWT token + user object.
3. Frontend stores the token in localStorage via the useAuth hook.
4. Every outgoing API request attaches the token via Axios interceptor.
5. On 401, the interceptor clears localStorage and redirects to login.
6. Logout removes the token and user from localStorage.
   Token lifetime: 1440 minutes (24 hours) by default.

--------------------------------------------------------------------------------
DARK MODE
--------------------------------------------------------------------------------

- Controlled by the Tailwind `darkMode: 'class'` strategy.
- A no-flicker inline script in index.html reads localStorage before the
  page renders and immediately adds `class="dark"` to <html> if needed.
- The useTheme hook manages the toggle and persists the preference.
- Toggle button (🌙/☀️) lives in the Navbar.
- All components use dark: Tailwind variants for background, text, and borders.
